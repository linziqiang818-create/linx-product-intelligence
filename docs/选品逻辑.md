# 选品逻辑（写给 LINX 自己看）

这一页不是功能文档，是选品判断的底层共识。所有评分、排序、规则、界面呈现都从这里推导。
改评分模型、改硬性规则、改界面之前，先回来读一遍，确认没有违背这里的方向。

## 1. 这个工具到底在找什么

用户的选品方式：看到一款不错的产品，**不是让工厂复刻一个一模一样的去亚马逊跟卖**，
而是借鉴它被市场验证过的优点（造型、结构、场景、功能组合），做适当改款，再开发自己的产品。

所以 LINX 的本质不是"找出好产品"，而是**找出值得借鉴的素材**：

开发偏好校准中的 `want / maybe / reject` 是对投入开发资源的判断，不是对竞品整款复制的承诺。样本可以只借鉴一个明确的局部元素或做法；记录时要把产品事实、AI 猜测和用户确认的开发原因分开。该样本记录不自动进入正式产品库或第二大脑偏好学习，待样本足够后再分析条件组合。

- 一款产品不需要"整体优秀"才有价值——只要它身上有被验证过的元素值得搬进改款方案，它就是好素材。
- 反过来，一款"各方面都不错"的同质化大路货，可能恰恰没有借鉴价值（没有差异化增量，只能拼价格）。
- 正式第二大脑仍以产品为单位排序，不把元素拆散打分。开发样本可明确记录“整款参考”或“只借鉴局部”；局部值得借鉴不代表复制整款，也不自动改变正式排序。

评分与排序应该奖励的是：**被验证的元素 × 尚未被填满的缺口**，而不是"这款产品整体多能卖"。
排序结果本身就是分数的呈现，分数本身不需要展示给用户。

## 2. 好素材的两大类

### 蓝海里的红海（冷门类目里被验证的需求）

- 类目 / 场景本身冷门：供给少、竞争少（蓝海）。
- 但里面的产品已经出现稳定销量、持续出单（红海特征）——需求被别人用钱验证过了。
- 对应信号：细分场景词（reception / nail desk / coffee bar / dog crate furniture…）＋ 月销稳定 ＋ 新品也能出单。
- 为什么好：需求真实性已验证，试错成本低；冷门意味着广告便宜、权重容易起。

### 红海里的蓝海（热门类目里没被满足的缺口）

- 大类目竞争激烈：需求大盘已被验证（红海）。
- 但某个细分组合还没人做好：造型 × 功能 × 场景 × 人群 × 价位的组合空缺（蓝海缺口）。
- 对应信号：类目大盘销量高 ＋ 现有产品评分偏低有明确抱怨点 / 评论壁垒低 / 客单价留得出升级空间。
- 为什么好：需求规模不用赌，缺口就是改款的落点。

### 共同结构

两者是同一个公式的两面：**用红海的信号验证需求，用蓝海的位置确定缺口。**

- 纯蓝海（需求未验证）→ 赌博，不是素材。
- 纯红海（无缺口）→ 拼价格，改款没有落点，也不是素材。

## 3. 需求怎么算"被验证"（用户确认，2026-09-17）

看三样东西：**上架时间、月销、当时的售价**。

- 近期上架 ⇒ 评论少 ⇒ 买家对它的信任少。这种情况下月销还不错，说明需求是真的，不是靠评论堆出来的。
- 价格能接受 ⇒ 这个价位有人买单，我们切入后有空间。
- 三者同时成立就是**切入窗口**：需求真实、评论壁垒尚未形成、价位已被验证。这是最强的单一信号。
- 代码对应：`assess.mjs` 里 `entryWindow = 上架 ≤ 180 天 && 月销 ≥ 30 && 评论 < 100`，命中时机会分加 6 并给出信号文案。
  评论上限只用来防异常（变体合并继承了老评论的"假新品"），不是独立门槛——上架近本身就意味着评论少。
- 例外——老店铺垂直类目（判法由 LINX 按用户习惯设定，2026-09-17，用户可修正）：
  上架 ≥ 1 年、评论 ≥ 300、月销仍 ≥ 50 的产品，不算切入窗口（评论壁垒已厚，正面拼评论不划算），
  但长期稳销说明它的造型与功能经过了长周期验证，仍值得整款借鉴。
  代码对应：`longProven` 命中时机会分补偿 2 分（抵掉评论 ≥ 1000 的拥挤惩罚），并给出"长周期验证"信号；
  不与切入窗口叠加。

### 价格带（用户确认，2026-09-17）

- 自有产品预期售价**不低于 150 美元**。
- 竞品卖 140 美元的也可能有借鉴价值——借鉴价值不在 150 处截断。
- 公司现在最贵的产品约 550 美元；MDF 大货家具 **600 美元基本是峰值**。套装能超过，但很少、销量也不高、基本不做。
- 代码对应：`companyFit` 里 150–600 美元加 6 分（自有可做区），140–150 加 3 分（仅参考区），140 以下与 600 以上不加分。
  价格不做硬性清除，仍可用筛选栏限定。

## 4. 改款一般怎么改（用户确认，2026-09-17）

按出现频率从高到低：

1. **功能增减**——实际使用感受上的差异。最常用，最容易做出差异化和溢价。
2. **风格变化**——造型元素等外观上的差异化。同样最常用，用来突出自己产品的特点。
3. **场景融合**——把产品融进另一个场景（例：餐边柜融合进厨房岛台）。可以做，但**单纯把同一个产品换个使用场景卖是蠢的**：每个产品都有它特定的一个或多个使用场景，场景迁移必须伴随产品形态的真实变化。
4. **材质替换**——少数情况。主体材质以 MDF 板为主，竞品也以此为主，基本不在材质上做文章。
5. **尺寸**——基本不大改。竞品卖得好说明尺寸本身没问题，大改尺寸反而容易出事。

对评分的含义：一款产品身上"可以加减的功能"和"可以替换的造型元素"越清晰，改款落点越明确，作为素材的价值越高。
尺寸和材质不是差异化维度，不要在这两个维度上奖励"独特性"。

功能模块的权重（用户确认，2026-09-17）：充电模块、升降、隐藏收纳、旋转这几类实际都会有溢价，但要看具体产品，
不是随便哪个产品加上某个功能都能溢价。**现阶段各功能元素权重保持相同**，等用户后续对"哪个更好"有具体判断再拆开。
功能负面清单（看起来花但卖不动）用户认为会很少——筛出来的产品不会那么差——**往后放，不催**。

### 套装与座椅怎么处理（用户确认，2026-09-17）

- **套装不能一刀切清除。** 功能组合套装（办公桌 + 文件柜等）有好产品会尝试做，保留。
- **椅子类目整体不做，带座椅的套装也不做**：桌椅套装、吧台桌 + 转凳、岛台 + 凳、茶几 + 储物凳、梳妆台 + 凳都清。
  缝纫桌带轮子这种是桌子，不受影响。规则 `category:seating`，判定方式见第 5 节。
- 同款多件装（床头柜 ×2、柜子 ×2）是销售形态不是组合，保留（用户数据里 216 款，绝大多数在池，说明一直在做）。
- 带镜子的套装、浴室柜套装已由现有镜面 / 浴室规则处理，不需要新规则。
- Hall Tree / 玄关鞋凳带长凳是公司在做的品类，继续保留；单独的储物长凳（Storage Benches）现状保留（坐垫例外规则本来就允许）。
- 含壁炉的产品**不清除**：壁炉组件不一定自制，可以像冰箱柜留冰箱位一样留壁炉位，或去壁炉改储物。
  标记 `flags.fireplaceSlot`，卡片显示"壁炉 → 留位或改储物"可改款。
- 办公桌 + 文件柜被普货规则清掉的（多为电动升降桌）维持现状：电动升降桌不做是既定边界。

## 5. 规则怎么判：多信号，不能只看标题（用户强调，2026-09-17）

标题里出现某个词，不等于产品就是那个东西："for 6 chairs" 是餐桌的容量描述，"chair rack" 是放椅子的推车，
"with mini fridge" 往往只是卖冰箱柜。**一定要标题、类目、价格、主图合起来判断，明确判断出来不符合才清；判不清的留在池里让用户纠错。**

写清除规则的固定套路（座椅规则是第一个按此实现的，后续所有清除规则照此办理）：

1. **先去反证**：容量描述、配件 / 器具、"不含 X"这类写法先从文本里去掉，再做匹配。
2. **只认明确写法**：套装词 + 目标词、"with 3 Stools"、"- 2 Bar Stools" 这种明确包含的写法才算证据；单独出现一个词不算。
3. **类目交叉确认**：单件产品必须类目也确认才清；类目是"安全类目"（推车 / 玄关 / 鞋柜 / 缝纫收纳等）的一律不清。
4. **主图引擎看不了**：规则没有视觉能力，主图判断靠用户在卡片上一眼决定，规则只负责"明确不符合"的那部分。
5. **每条规则配测试**：既测该清的，也测"标题带词但不该清"的反例（餐桌 for 4、椅子收纳车、边几、缝纫椅）。

## 6. 对界面呈现的约束

- 机器看的信号不给用户看：推荐分、排名编号（#1 #2…）、偏好理由、机会信号，都是排序的内部依据，**排序结果本身就够了**。
  用户看一眼产品主图就能判断有没有开发可能，卡片只保留他判断时需要的客观信息：主图、价格、月销、增长、利润、材质标签。
- 卡片上唯一保留的"理由"是清除原因（已清除视图），因为纠错 / 捞回时要看它。
- 偏好理由、机会信号、历史校准等解释性文字放在详情抽屉，供未来复盘，不进卡片。

## 7. 第二大脑的收敛原则（锚点模型，2026-09-18 定稿）

三层是漏斗：**产品库（全部）→ 适配池（过硬性条件的全体，默认层）→ 第二大脑（模型按你的正向偏好挑出的精选层）**。第二大脑必然比适配池少，随反馈收敛到"打开随便看都是想开发的"。

- **锚点**：你动过手的产品，每个产品聚合为一个锚点（封顶 ±6，反复点击不重复计票）。👍感兴趣 +3、移出 −4 为主锚点；收藏 +1 弱参考（收藏原因复杂，只算参考票）；捞回 +3。全部按 4 个月衰减一半。
- **泛化只走"产品对产品的高度相似"**：相似度 = 同小类 3 + 同细分场景 3 + 同造型元素 2 + 同结构 1（封顶 2）+ 大类/材质/价格带各 0.5；**≥4 算高度相似**。"都是板式家具"约 1 分，永远不算相似——这是 2026-09-18 的核心修正：移出 224 款不代表 224 个类目不行。
- **负向按移除原因分流**：普货只连同样平庸的款（有辨识度的豁免）、同质化只连拥挤簇（库里近亲 ≥20 款）、材质只连同材质同做法、类目不做才连类目、无原因按产品级高度相似。
- **偏好分 ≥40 自动升入第二大脑**：一个 👍 对高度相似款（相似度 ≥5）约给 46 分，泛泛沾光过不了线。升入时的 👍 是持久锚点：恢复自动判定后模型依然会选它。
- **收藏即钉入第二大脑**（产品本身一定在精选层），但它对相似款的泛化按弱票 1 分计。
- **手动钉住永远赢过模型**；负向只排除候选，不动你钉住的。
- **视觉通道（本地 CLIP，零费用）**：主图向量（512 维，transformers.js 本机 CPU 推理）作为第三相似度通道——比例、质感、设计完成度这些属性表达不了的"看一眼就知道像不像"由它捕捉；新品入库自动补算。
- **诚实底线**：正负锚点同时高度相似 → 分数相抵偏保守，两款都留在你眼前。模型把清晰的判对、把模糊的上交，不装懂。
- 历史教训：属性格子模型曾把 224 次移出放大成 3,639 款自动降层（2026-09-18 废弃重写）；v1 历史校准样本同日移除——只有你本人的实时操作配学习。

## 10. 三层池"移动制"改造（用户确认，2026-09-18）

灰掉产品（半透明 + 不感兴趣标签）的设计废除。产品永远"住在"某一层，手动动作 = 把产品搬到该去的层：

- **产品库**：所有导入的产品。被硬性条件筛掉的带原因标；👍 拉入适配池，菜单可「直通第二大脑」。
- **适配池**（默认层）：过了硬性条件的**全体**产品，按推荐分排序。收藏和 👍 会把同款气质的升入第二大脑；不想要的移出（只影响那一款）。
- **第二大脑**（精选层）：正向偏好分 ≥40 的（模型从适配池挑的）+ 你手动升入/收藏钉住的。👍 是「感兴趣」强化信号，👎 降到适配池。

分层判定（2026-09-18 锚点模型定稿）：**placement（硬性规则）+ tier（手动钉住，永远优先）+ prefScore ≥40（模型正向挑选）**。
白纸期（还没有锚点）默认全在适配池；每一条 👍/收藏/捞回都成为正向锚点，把高度相似的同款气质产品升上来；移出按原因分流只排除高度相似的款，绝不连坐类目。

配套机制：

- 每次移动 = 一条带权重的学习事件（+4 拉上 / −4 降下·移回 / +3 感兴趣），原因（材质做不了等 5 种）随事件落库；**其中只有正向事件进入偏好学习**，负向事件仅作历史记录。
- 移动后右上角弹 toast（7 秒），可**撤销**——撤销会删除学习事件并精确还原移动前的层级/覆盖/标记，等于这事没发生过；没选原因的降级可在 toast 里「补记原因」。
- 右上角「错题本」三页签：硬筛复查清单（按原因分组、捞回、同类连坐提示）、规则错题统计（捞回率 >20% 标"可能太严"，跳设置改规则）、手动调整历史（每条可撤销最新一条）。
- 「重置偏好」同时清空手动钉住的层级，回到白纸。
